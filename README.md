# AETHER — 即時運算視覺實驗室

三座完全跑在 GPU 上的場景，一顆會撞東西的球在裡面。**零依賴、零建置、零打包器**：
沒有 npm、沒有框架、沒有函式庫，`index.html` 雙擊就開。所有東西都是 `<canvas>`、
原生 ES modules，與手寫 GLSL。

```
index.html          ← 直接開這個
styles/             ← reset / tokens / shell / ui
src/
  main.js           ← 應用外殼：一個 context、一個 rAF loop、一個 pointer、一個 router
  core/             ← 引擎（與場景無關）
    gl.js           WebGL2 context、材質、render target、全螢幕三角形
    program.js      著色器程式 + uniform 反射
    clock.js        單一 rAF loop，模擬時間與真實時間分離
    pointer.js      滑鼠／觸控／筆統一輸入
    agent.js        「游者」：一顆球 + 因加速而剝離的慣性小球，三個場景共用同一顆
    router.js       hash 路由，參數即 URL
    signal.js       ~70 行細粒度反應式系統
    perf.js         GPU timer query + FPS 環形緩衝
  ui/
    widgets.js      自訂元素（slider / switch / segmented / xy-pad）
    panel.js        schema → 控制面板
    chrome.js       tabs、效能 HUD、toast
    cmdk.js         指令面板（模糊搜尋）
  shaders/common.js GLSL 共用區塊（simplex、curl、色彩、tonemap）
  scenes/           三個場景，各自宣告參數 schema
    archive/        封存的場景（不在執行中的 app 裡，見該目錄的 README）
tools/verify.mjs    ← 零依賴的無頭驗收工具（見下）
```

## 三個場景

編號是型錄號碼、不是順序：01 已封存在 `src/scenes/archive/`，其餘保留它們被寫出來時的號碼。

| # | 場景 | 核心技術 | 游者在裡面做什麼 |
|---|------|----------|------------------|
| 03 | **SDF 光線行進** | 整個 3D 場景 **0 頂點 0 三角形**：一道 fragment shader 用 sphere tracing 走進隱式曲面。IQ 軟陰影、5 取樣環境遮蔽、一次鏡面反射彈跳、jitter + 時間累積的免費 TAA。 | 牠是**真正的幾何**：球體與剝離的小球直接進 `map()`，因此自動獲得真實的軟陰影、環境遮蔽與鏡面反射。撞上星體會反彈，撞擊點在星體表面推出一圈擴散的漣漪。 |
| 02 | **Navier–Stokes 流體** | Stam 的 stable fluids：半拉格朗日反向追蹤對流（任意 dt 都無條件穩定）→ 渦度強化 → Jacobi 迭代解壓力泊松方程 → 投影成無散度場。每幀 8–40 道 pass。 | 牠**就是**攪動者。球體與最近剝離的幾滴各自注入速度與染料，渦度強化再把它捲成漩渦。你不直接碰流體，你牽著一顆球走，尾流就是畫。 |
| 04 | **Gray–Scott 反應擴散** | 兩行偏微分方程長出珊瑚、迷宮、細胞分裂與孤立子。九點拉普拉斯算子、每幀 16 個子步、環面邊界（`REPEAT` wrap，所以圖樣可無縫平舖）。 | 球體把化學場推回乾淨基質，切開一條通道 —— 而乾淨基質是這個模型的**穩定**狀態，所以通道不會自己癒合。剝離的小球再往通道裡撒下菌落，尾跡於是開花。 |

## 游者

三個場景共用同一顆球，牠住在 App 層而不屬於任何場景 —— 換場景時把同一顆、同樣的位置與動量、正在轉彎到一半的球交給下一個渲染器（驗收工具會檢查這件事）。

牠活在一個「正規空間」（原點附近半徑 1.9 的球）裡，每個場景把那個空間映射到自己的座標：3D 場景映到世界單位，2D 場景映到 UV。指標的目標點則反向穿過各場景**自己的**相機基底換算回來 —— 所以「牠跟著我的游標」在鏡頭繞了半圈之後仍然成立，這是天真的螢幕座標映射做不到的。

### 本體是一顆球，拖尾不是身體

跟在後面的不是尾巴，是**因加速而從本體剝離的小球**。每一滴有自己的速度、自己的阻力、自己的短命。沒有任何一節是鏈條，沒有骨架 —— 拖尾純粹是「這顆球被加速了」的結果，正如一團液體被甩動時會發生的事。

**剝離率由加速度驅動，不是速度。** 等速穿過虛空的東西沒有理由散開；被硬拽進轉彎的東西才有。巡航時仍然掉一點，否則牠飄著的時候看起來像死的。

負擔得起的場景（03）會用 **smooth-min 把小球融回本體**：剛剝離的那一滴還在融合半徑內，所以還牽著；等牠飄開，脖子變細、然後捏斷。一個運算子，就讓一組各自獨立的球讀起來像一團黏性液體。

**它們一定會消散**，否則畫面上會堆滿垃圾：固定 10 個槽位的池子（硬上限，不可能累積），每滴獨立壽命，半徑用 `pow(life, 0.45)` 收縮 —— 先維持體積、最後才塌縮，不會突然彈掉。

### 運動與碰撞

**轉向**用 Reynolds 的作法：算出期望速度，然後朝它加速。速度同時有上限與**下限** —— 會突然停住的東西讀起來是粒子，不是有質量的物體。

上面只架了兩個衝量原語：`reflect`（繞法線反射，帶恢復係數）與 `displace`（純位移）。碰撞回應只需要這兩個，**而未來要做的「在星體之間跳躍」也只需要這兩個**。

03 的星體位置從 shader 移回了 CPU。這花掉九個 uniform，換到 shader 給不回來的那件事：能在 JavaScript 裡問「東西在哪」—— 這正是碰撞、以及任何建立在碰撞之上的東西所需要的。

撞擊時：先把球推出表面（**位置先解，衝量後給**，否則下一幀會再撞一次，一次接觸變成連續嗡鳴），再反射速度，然後在接觸點登記一圈漣漪。漣漪是加在**距離場本身**上的一項 —— 沒有網格可以推，所以波不是被畫上去的，波**就是**表面。振幅刻意壓低：太大會破壞距離場的 Lipschitz 界，球體追蹤器會直接穿過表面。

漣漪的圓心每幀從它的宿主星體重新算，不是撞擊當下烙在世界座標上 —— 星體在公轉，凍結的圓心會從它該待的表面滑掉。

## 值得一看的幾個決定

**Uniform 反射。** GPU 在連結程式時就已經知道每個 uniform 的名字、型別與位置，所以要求作者
在 JS 裡再抄一遍純粹是重複。[`core/program.js`](src/core/program.js) 讀一次反射資料，
之後 `prog.use({ ... })` 依型別自動分派到正確的 `gl.uniform*`，並把材質綁到自動指派的
texture unit。整個專案沒有一行 `getUniformLocation`。

**沒有建置步驟，所以 GLSL 就是 JS 模組。** 沒有 `#include`，共用著色器碼就放在
[`shaders/common.js`](src/shaders/common.js) 的字串常數裡用 `${}` 組合。這不是妥協 ——
它意味著著色器由瀏覽器自己的模組圖管理，沒有前處理器需要除錯。

**一個超大三角形，不是兩個。** 覆蓋全螢幕用 `(-1,-1) (3,-1) (-1,3)`：沒有對角接縫、少一個頂點，
而且 GPU 不會在斜邊重複光柵化同一個 pixel。

**Ping-pong 是型別的一部分。** `DoubleTarget` 把 `.read` / `.write` / `.swap()` 包在一個物件裡，
消滅了 GPGPU 最常見的 bug：忘記自己在哪一半。

**參數即 URL。** `#/fluid?curl=28&dyeDiss=0.6` 是你眼前畫面的完整描述。拖曳 slider 時用
`replaceState` 寫回位址列 —— 值得分享的狀態就是能寄給別人的狀態。

**自訂元素包住原生控制項。** 每個 widget 底下都是真正的 `<input type=range>` /
`<button role=switch>`，只有像素是我們的。鍵盤操作、螢幕閱讀器語意、IME 行為全部來自平台。

**時間分兩種。** `clock.dt` 是模擬時間（可暫停、可縮放），`clock.wallDt` 是真實時間（永不為 0）。
暫停場景不會讓 UI 動畫卡住；一個異常長的幀（切回分頁、著色器重編譯）永遠不會被交給
積分器 —— dt 上限鎖在 1/20 秒。

## 快捷鍵

| 鍵 | 動作 |
|---|---|
`1`–`3` | 切換場景
`Ctrl`+`K` | 指令面板（模糊搜尋所有場景與動作）
`Space` | 暫停 / 繼續
`.` | 暫停時前進一幀
`R` | 重設場景
`S` | 存成 PNG
`P` | 顯示 / 隱藏參數面板
`Z` | 禪模式（隱藏所有介面）
`F` | 全螢幕
`?` | 快捷鍵一覽

**移動指標就能帶著游者跑** —— 每個場景的參數面板裡都有「行為」可以切成漫遊 / 跟隨 / 迴避。
在 03 裡把牠導向星體就會撞、會彈、會濺起漣漪。畫布上拖曳則是直接互動
（繞行鏡頭 / 播種化學物質），滾輪縮放。

### 這條路通往哪裡

03 已經具備一個「在星體之間跳躍」的遊戲所需要的全部東西：CPU 端知道每顆星體在哪、
球體有可反射的速度、接觸點會被登記下來、恢復係數是一個滑桿。還缺的是規則 ——
目標、計分、失敗條件 —— 而不是物理。

## 需求

WebGL2 + `EXT_color_buffer_float`。每個場景都把模擬狀態存在浮點貼圖裡，沒有浮點 render target
無法運作 —— 缺少時會顯示明確的說明頁，而不是一片黑。

沒有伺服器也能跑嗎？ES modules 受 CORS 限制，所以 `file://` 直接開會被瀏覽器擋。用任何靜態伺服器：

```bash
node tools/verify.mjs --serve     # 內建的，零依賴
# 或
python -m http.server
```

## 驗收工具：`tools/verify.mjs`

同樣零依賴。它用 Node 內建的 `WebSocket` 與 `fetch` 直接講 Chrome DevTools Protocol ——
沒有 puppeteer、沒有 playwright、沒有測試框架。協定就是 socket 上的 JSON，這就是全部的依賴表面。

```bash
node tools/verify.mjs                # 每個場景載入、渲染、截圖，回報任何 console error
node tools/verify.mjs --interact     # 端對端互動驗收（真的去拖曳滑鼠、按鍵）
node tools/verify.mjs --responsive   # 手機 / 平板 / 筆電 / 超寬視窗版面與像素預算
node tools/verify.mjs --head         # 開可見的瀏覽器視窗
node tools/verify.mjs --serve        # 只開靜態伺服器
node tools/verify.mjs --eval probe.js --at "#/flow"   # 在頁面裡執行探針，檢查活的 GPU 狀態
```

截圖輸出在 `tools/shots/`。除了抓圖之外它還會斷言：畫布不是單一顏色（全黑代表沒渲染）、
`gl.getError()` 乾淨、沒有未捕捉的例外。

`--interact` 的 22 項檢查涵蓋：intro 關閉、指標事件真的進到畫布、拖曳注入染料、
游者朝指標轉向、`Ctrl`+`K` 開啟面板、模糊搜尋過濾、面板導航、**球體撞上星體**、
**撞擊留下漣漪**、**球體剝離出慣性小球且數量在池子上限內**、游者跨場景保留動量、
拖曳繞行鏡頭、數字鍵切換場景、參數往返 URL、暫停真的停住時鐘、`.` 前進一幀、
禪模式、快捷鍵表、tab 點擊、指示器追蹤，以及全程零 console error。

### 它抓到的六個真 bug

1. **`[hidden]` 被 CSS 打敗。** `.fallback { display: grid }` 的優先權高於 UA 對 `[hidden]` 的
   `display: none`，所以「需要 WebGL2」的錯誤畫面一直蓋在正常運作的網站上面。
2. **切換場景時 render target 停在 2×2。** 換場景不會改變畫布尺寸，所以 `_resize()` 的
   「有變化嗎？」提早 return，新場景永遠拿不到真正的解析度。
3. **`gl_PointSize < 1` 的粒子被硬體丟棄。** `ALIASED_POINT_SIZE_RANGE` 在這張 GPU 上從 1 開始，
   而透視除法把點的大小算到 0.29 —— 26 萬個粒子一個都沒畫出來。
4. **拖曳在開始的那一幀就被取消。** 用 `setPointerCapture` 之後又監聽 `pointerleave` 來結束拖曳
   是錯的：呼叫 capture 本身就會觸發一組 out/leave。
5. **光線行進場景上下顛倒。** `right` 算成了 `cross(worldUp, fwd)` 而不是
   `cross(fwd, worldUp)`，負號穿過下一個外積傳給 `up` —— 格線地板一直畫在天空裡，
   而場景夠對稱，對稱到這件事看起來像是刻意的構圖。
6. **View Transition 被中斷時丟出未處理的 rejection。** 切場景比轉場動畫還快是正常操作，
   不該變成 console error。

第 5 個特別值得一提：它是被截圖裡「格線出現在地平線上方」這個細節抓到的，
而不是被任何斷言抓到的 —— 這正是為什麼驗收工具要輸出可以用眼睛看的東西。
